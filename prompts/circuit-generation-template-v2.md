# 电路生成模板 v2（强化导入布局 · 摆放整齐 / 连线不混杂）

> **v2 相对 v1 改了什么**
>
> v1 只有一条「元件行按信号流顺序书写」。实测下来：导入后主链路**方向**是对的，
> 但元件在图纸上的**具体位置仍是 Multisim 自己排的**，飞线大量交叉，整理要花 20~30 分钟。
>
> v2 在 v1 基础上新增 4 条硬约束，并把「第 3 部分」从单纯的 ASCII 图，
> 升级为 **3a 网格坐标表 + 3b ASCII 图**：
>
> | 新增约束 | 解决什么 |
> |---------|---------|
> | ⑦ **网络标签优先** | 相距远的元件不再靠长飞线，改用同名网络 → 连线数量骤降 |
> | ⑧ **信号流单调向右** | 杜绝"信号回流"，从根上消除回绕交叉 |
> | ⑨ **扇出 ≤ 4** | 一个节点挂太多引脚必然交叉，超限必须拆节点 |
> | 3a **网格坐标表** | 给每个元件 (列, 行, 旋转)，照表摆 5 分钟搞定 |
>
> ⚠️ **诚实边界没有变**：`.cir` 网表**不包含任何坐标信息**，v2 依然不能让 Multisim
> 自动摆出一张整齐的图——这是格式限制，任何提示词都改不了（见 `docs/faq.md` Q2）。
> v2 真正的作用是：把「导入后整理」从 ~30 分钟压缩到 ~5 分钟（照 3a 表摆位 + 打网络标签）。
> 想要**零整理**的整齐图，只有换带坐标的格式（LTspice `.asc` / EasyEDA JSON），文末有说明。

## 使用

复制下面 ``` 代码块里的全部内容，替换 `{{...}}` 占位符后发给任意大模型。
占位符填写规范见 [`prompts/README.md`](./README.md)，与 v1 完全一致（仍是 12 个）。

```text
你是精通 NI Multisim 14.3 的电路仿真工程师，熟悉 SPICE 网表语法及 Multisim 网表导入兼容性。

任务：
设计一个【{{电路名称}}】，输出可直接用 Multisim File → Open 导入的 .cir 网表。
我要用【{{验证仪器}}】验证【{{验证目标}}】。

电路规格：
- 性能指标：{{性能指标}}
- 电源：{{电源规格}}
- 输入：{{输入信号}}
- 负载：{{负载}}
- 有源器件：{{有源器件及型号}}

具体元器件要求（必须使用）：
{{元器件清单：每行一个，含网表标号/Multisim库路径/参数}}

- 计算说明：{{关键设计计算}}
- 信号流向：{{从输入到输出的信号流向描述}}

硬性约束（必须遵守）：
1. 分析指令只允许：.OP / .AC / .TRAN / .DC
2. 禁止：.MEAS .FOUR .NOISE .TF .SENS .STEP .TEMP .MC .PROBE .PLOT .PRINT
3. 黑盒策略：含有源器件时允许 .MODEL，禁止 .SUBCKT
4. 元件值写法：10k / 1k / 5（禁止科学计数法；.MODEL 内参数除外，如 14.34F）
5. 节点名全英文大写；首行标题注释；末行 .END；ANSI 编码
6. 【行序 = 信号流】元件行必须按物理信号流顺序书写，一行只写一个元件；
   输入源在最前、电源行（VCC / VDD / VEE）统一放最后；
   .MODEL 行放元件行之后、分析指令之前
7. 【网络标签优先】节点名必须语义化且简短（不超过 6 个字符），
   如 IN / OUT / BASE / COL / EMIT / VCC / THR / DIS / CTRL / RESET；
   禁止使用 N1、N2、A、B、NET01 这类无意义名字。
   两个在图上相距超过 2 格的元件之间，一律用「取同一个节点名」来连接
   （导入后等同于打了网络标签），不允许画跨越图面的长飞线
8. 【信号流单调向右】每个元件的输入节点，必须来自它左侧（更早出现）的元件或信号源。
   不允许出现「第 i 行元件的输出，被送回第 j<i 行元件的输入端」这类回流 / 回绕连线。
   确有反馈需求的（如运放反馈、振荡器正反馈），请在第 3b 节 ASCII 图与第 5 节连线表里
   显式标注「反馈支路」，并说明它在图上走最下方一行
9. 【扇出限制】单个节点建议不超过 4 个元件引脚（含芯片引脚）。
   超过 4 个必须拆成两个节点名（中间用 0 欧电阻或直接导线相连），否则导入后飞线必然交叉。
   注意：分压偏置电路的基极节点天然有 4 个连接（上偏置 / 下偏置 / 耦合电容 / 管子基极），
   属正常情况，可在第 3a 节用「同列垂直对齐」来避免交叉
10. 【电源与地统一】所有 VCC / VDD / VEE 行集中在元件行最后；
    地一律用节点 0；全网只能有一个地网络，禁止出现 VSS2、GND2 之类的第二地

输出格式（严格按以下 8 部分，顺序不变）：
## 1. 完整 .cir 网表代码（一个代码块，注明文件名与编码）
## 2. 元件清单表（网表标号 | Multisim 库路径 | 参数 | 所在列）
## 3a. 网格坐标表（标号 | 列 x | 行 y | 旋转角度 | 摆放说明）
## 3b. ASCII 布局图（严格按 3a 的坐标绘制；信号左到右，电源顶、地底）
## 4. 导入后整理步骤（黑盒替换 / 按 3a 坐标摆位旋转 / 打网络标签 / 连线）
## 5. 连线表（序号 | 从 | 到 | 是否用网络标签 | 建议走线方向）
## 6. 仪器设置（XFG1 / XSC1 / XBP1 端子与面板参数 + Grapher 游标读数法）
## 7. 验证值 + 易错点（理论计算表 + 3 个典型接错方式的读数表现
     + 1 条「位置错乱 / 连线交叉」的自查与修正步骤）

补充要求：
A. .cir 文件内所有注释使用英文（Multisim 导入器对非 ASCII 字符敏感），
   中文说明请放在第 2~7 部分，不要写进网表。
B. 每行长度不超过 132 字符，超长用 + 续行。
C. 输出第 7 部分时，理论值必须能用网表里的元件值手算复现，
   并额外给出「这 3 个数如果测出来偏了，最可能是哪里接错」。
D. 第 3a 网格坐标表按 Multisim 默认栅格（0.1 inch = 1 格）给出**相对**坐标：
   列 x 从 0 开始向右递增，行 y 从 0 开始向下递增；旋转角度只能取 0 / 90 / 180 / 270。
   规则：主信号链上的所有元件 y 必须相同（排在同一行）；
   电源与去耦电容放在 y 更小的上方；地回路放在 y 更大的下方。
E. 第 5 部分「建议走线方向」只能填以下四种之一：
   短直线 / 先横后竖 / 先竖后横 / 网络标签（免走线）。
   出现"斜线"或需要跨越其它元件的长线即为不合格，必须改用网络标签。
```

## 3a 网格坐标表长什么样（001 电路示例）

| 标号 | 列 x | 行 y | 旋转 | 摆放说明 |
|------|------|------|------|---------|
| VIN | 0 | 2 | 0° | 最左，信号源 |
| RB | 4 | 2 | 0° | 与 VIN 同一行（主信号链） |
| Q1 | 9 | 2 | 0° | TO-92，E 下 / B 中 / C 上 |
| DLED | 9 | 1 | 90° | Q1 正上方，阴极朝上 |
| RC | 9 | 0 | 90° | 再往上一格 |
| VCC | 4 | 0 | 0° | 顶部电源符号，用网络标签连 RC |
| GND | 4 | 4 | 0° | 底部地符号 |

主信号链 `VIN(0,2) → RB(4,2) → Q1(9,2)` **全部在 y=2 这一行**；
集电极回路垂直向上串 DLED、RC 到 VCC；地回路在 y=4。
照这张表摆，飞线只剩 3 条短直线 + 1 条竖线。

## 局限与"真正彻底"的解法

v2 能把整理时间压到 5 分钟，但**做不到零整理**——因为 `.cir` 里根本没有坐标字段。
如果你确实需要"一导入就是整齐的图"，有两条路：

1. **换 LTspice `.asc`**：XML 格式，每个元件都能精确指定 X/Y 与旋转角。
   可以在提示词里加一条"额外输出一份 LTspice .asc，元件坐标按 3a 表 × 16 像素"，
   至少能拿到一张能看的原理图（仿真仍在 Multisim 里做）。
2. **换 EasyEDA / 立创 EDA JSON**：同样带 x/y/rotation，网页端可直接打开，
   还能一键导出 PDF / 图片。适合做实验报告或课件。

这两条都属于"换个交付格式"，不是改提示词能解决的——结论已写在 `docs/faq.md` Q2。

## 配套：已随 v2 落地的两条 lint 规则

v2 的 ⑧ ⑨ 两条原本靠人眼检查，现已可自动化（见 `scripts/cir_lint.py`）：

| 规则 | 级别 | 检查内容 |
|------|------|---------|
| `W-FANOUT1` | warn（`--strict` 会计入失败） | 同一节点出现 **≥ 5** 次 → "扇出 N，导入后连线易交叉，建议拆节点或用网络标签" |
| `I-SPAN1` | info（**永不计入失败**） | 单个网络横跨 **≥ 4 个元件位** → "该网络会拉出一条横穿图面的长线，建议排成同列或加网络标签" |

**为什么 W-FANOUT1 的阈值是 5 而不是 3**：实测 002 电路的分压偏置基极节点
（`BASE`）天然连接 4 个引脚（耦合电容 C1、上偏置 R1、下偏置 R2、Q1 基极），
取 3 会误伤正常电路。阈值定为 ≥5 才既不误报、又能抓住真正的"总线式"节点。

**为什么 `I-SPAN1` 用 info 级别**：正常电路也会命中——例如 002 的 `COL`
（Q1 → RC → C2，跨 5 位）、003 的 `DIS` / `THR`（RA / RB → 555 引脚，跨 5 / 4 位）。
这属于"值得提醒但不该判失败"的排版问题，所以只作 info，`--strict` 不会因此变红。
实测现有 4 个网表：**0 error / 0 warn / 3 info**，CI 依然全绿。

## v1 与 v2 怎么选

- **v1**（`circuit-generation-template.md`）：现有 3 个种子电路的 `prompt-used.md`
  记录的是 v1，保留以保持可复现。
- **v2**（本文件）：从下一个新电路开始用，尤其是**元件多、连线复杂**的电路
  （共射放大、555、运放电路）收益最明显。现有 3 个电路的文档已按 v2 格式补齐
  3a 网格坐标表与"建议走线方向"列。
- 两者**硬性约束 1~5 完全相同**，v2 只是新增 6~10 并细化了第 3 部分，不会破坏 lint。
