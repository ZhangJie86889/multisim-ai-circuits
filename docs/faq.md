# FAQ（高频问题）

> 这里的答案都是**实测/已知结论**，不是猜测。如果你的情况与某条不符，
> 请开 Issue 说明 Multisim 版本与现象——很可能又是一个版本差异，值得补进来。

---

## Q1. 为什么导入后 `.OP / .TRAN / .AC` 这些分析指令被忽略了？

**已知结论**：Multisim 的网表导入器**对分析指令的支持是不稳定的**——
部分版本会读进来，部分版本直接丢弃，还有的读进来但参数错位。

**做法**：不要指望网表里的分析指令，导入后一律在 UI 里重设：

```
Simulate → Analyses and simulation
  ├ DC Operating Point  → Output 页加你要看的节点电压/支路电流
  ├ Transient Analysis  → 填 End time 与 Maximum time step（见各电路 README 第 6 节）
  └ AC Analysis         → Decade + 起止频率 + Output 加 V(OUT)
```

所以本项目把"分析指令"写进网表只是为了**让网表在语法上自洽**（也能给纯 SPICE 工具用），
真正的仿真参数请以各电路 README 第 6 节的表格为准。

> 同理，`.PARAM` / `.OPTIONS` / `.STEP` / `.MEASURE` 这类也是常被引擎忽略或报错的，
> 所以硬约束里直接禁掉了。**要参数扫描就走 UI 的 `Parameter Sweep`（Device parameter + List）**。

## Q2. 为什么导入后元件乱七八糟、图一点都不整齐？

**已知结论**：**这不是提示词能修的问题，是格式限制。**

`.cir` 网表**根本不包含任何坐标信息**——它只描述"谁连谁"。
Multisim 导入时会自己给元件排位置（大致按**元件行出现顺序从左到右**），
所以结果必然是"能连对，但摆得难看"。

**能缓解的**：

- 生成时约束**元件行按物理信号流顺序书写**，电源行放最后。
  这样导入后主链路至少是沿着信号方向排的（这是本项目硬约束第 6 条的由来）。
- `cir_lint.py` 的 `W-ORDER1` 会检查网表行序与 README 声明的 `SIGNALFLOW` 是否一致。

**不能缓解的**：要一张真正整齐的教学用图，只有两条路：

1. 照 README 第 3 节的 ASCII 图**手动摆一遍**（我们给了摆位和旋转角度）；
2. 换用**带坐标的格式**，如 LTspice 的 `.asc`（XML 里能精确指定每个元件的 X/Y）。

> 别信"改一下提示词就能让 Multisim 摆整齐"的说法。任何提示词都改不了网表没有坐标这件事。

## Q3. XFG1（函数发生器）的 Amplitude 和 Offset 到底怎么设？

**已知结论**：XFG1 上的 `Amplitude` 指的是**峰值（Vp）**，不是峰峰值（Vpp），
而且它是**叠加在 Offset 上**的。

| 想要的输出 | Amplitude | Offset |
|-----------|-----------|--------|
| 0 V ~ 5 V 方波（**001 电路要的**） | **2.5 Vp** | **2.5 V** |
| −5 V ~ +5 V | 5 Vp | 0 V |
| −2.5 V ~ +2.5 V | 2.5 Vp | 0 V |
| 1 kHz、20 mVpp 正弦（**002 电路要的**） | **10 mVp** | 0 V |

**公式**：`输出范围 = Offset ± Amplitude`，即
`Vmax = Offset + Amplitude`、`Vmin = Offset − Amplitude`。

**最常见错误**：想要 0~5 V，设成 `Amplitude 5 V + Offset 0 V` → 实际是 **−5 V ~ +5 V**。
在 001 电路里这会让三极管基极在负半周反偏，波形看起来"怪怪的但好像又能亮"。

面板上如果只显示 `Vpp`（部分版本/虚拟仪器），则 `Amplitude(Vp) = Vpp / 2`。

## Q4. 为什么我的 `.cir` 打不开 / 导入解析失败？

按出现频率排序的三个原因：

1. **文件里有非 ASCII 字符（中文注释最常见）**。
   实测网表里出现中文注释会让 Multisim 的网表导入器直接解析失败。
   → **网表注释一律用英文**，中文说明写在同目录 `README.md` 里。
   `cir_lint.py` 的 `E-ENC001` 会逐行报出非 ASCII 的行号。
   （这也是为什么我们的生成模板虽写了"行首 * 中文注释"，但补充要求 A 又强制改成英文——
   **以能导入为准**。）
2. **单行超过 132 字符**。经典 SPICE 的行长上限，超了可能被截断。
   → 用 `+` 续行（续行也要保持 ASCII）。`cir_lint.py` 的 `W-LEN01` 会报。
3. **用了不支持的指令**：`.PARAM` / `.OPTIONS` / `.MEASURE` / `.STEP` / `.SUBCKT` /
   `.INCLUDE` / `.LIB` … → 全部删掉。

排查顺序：先跑 `python scripts/cir_lint.py xxx.cir`，
它会把上面三类一次性报出来并给出行号。

## Q5. 仿真报 "singular matrix" / "floating node" / "Transient analysis failed"？

**已知结论**：几乎都是**悬空节点**导致的。

`singular matrix` = 导纳矩阵奇异 = 有节点没有到地的直流通路。常见情形：

| 现象 | 原因 |
|------|------|
| 忘了放 `GROUND` | 每个电路**必须且只能有一个**地（网络 0） |
| 信号源负端没接地 | `VIN` 的 `−` 悬空 |
| 某个节点只连了 1 个元件引脚 | 比如电容一端悬空、三极管某个脚空着 |
| 两个电容串联中间的节点 | 该节点没有直流通路 → 并联一个大电阻（如 `1MEG`）到地 |
| 运放输出悬空 | 加负载电阻 |

**排查方法**：`Tools → Circuit → Show Node Numbers`，
确认地网络的编号是 **0**，然后逐个节点数引脚——**每个非地节点至少要有 2 个引脚**。

`cir_lint.py` 的 `W-FLOAT1` 会直接告诉你哪个节点只出现了 1 次。

## Q6. LED 不亮 / 电流和算出来的差很多？

先查这三件事：

1. **极性反了**。LED 阴极（横杠一侧、短脚）应该朝向**电流流出**的方向。
   001 电路里是"电流从 VCC → RC → LED → Q1(C) → 地"，
   所以**阴极朝 RC/VCC 一侧，阳极朝 Q1 集电极**。
2. **`Vf` 取值不同**。`LED_red ≈ 2.0 V`、`LED_green ≈ 2.2 V`、`LED_blue/white ≈ 3.0~3.6 V`。
   换颜色不改限流电阻，电流会明显变化。
   用 XMM1 的**二极管档**或看 Grapher 里 LED 两端电压，就能反推实际 `Vf`。
3. **Multisim 库里的 LED 模型参数与网表 `.MODEL` 不一致**。
   黑盒替换后，实际用的是库件模型，`Vf` 可能差 0.2~0.5 V，
   对 3 mA 这种小电流电路就是 20 % 以上的偏差。
   **以实测为准，回头修限流电阻**。

**快速判据**：`I = (VCC − Vf − Vce(sat)) / RC`。
测出来偏小 → `Vf` 偏大或 `Vce(sat)` 偏大；测出来偏大 → 反之。

## Q7. NE555 接好了不振荡，输出一条直线？

按概率排查：

1. **`XU1` 没做黑盒替换**。这是 003 电路最容易踩的坑：项目硬约束**禁止 `.SUBCKT`**，
   网表里 `XU1 ... NE555` 只是个**没有内部模型的空盒**。
   → 必须换成 `Mixed / TIMER / LM555CN`。没换之前跑出来的任何结果都是无效的。
2. **THR（6 脚）和 TRIG（2 脚）没短接**。这是无稳态接法的灵魂。
   漏掉它，电容能充到 2/3 VCC 让输出变低，但**永远不会翻回高电平** → 输出卡在低电平。
3. **RESET（4 脚）悬空或被接地**。必须经 10 kΩ 上拉到 VCC，否则随机复位或完全不振。
4. **不起振（上电后一直停在某个状态）**。
   在 `Transient Analysis` 里勾选 `Set initial conditions → User-defined`，
   或临时给 `CT` 设一个非零初值帮助起振。

**555 输出高电平不是 VCC**（典型 `VCC − 1.3 V` ≈ 3.7 V @5 V），测到 5 V 说明用的可能是 CMOS 版 TLC555。

## Q8. Grapher 的游标怎么读数？

1. 跑完分析自动弹 Grapher → 工具栏点 **Cursor**（或 `View → Show/Hide Cursors`）。
2. 拖 **Cursor 1 / Cursor 2**，面板上直接显示 `dx`（横坐标差）和 `dy`（纵坐标差）。

| 要测什么 | 游标怎么卡 |
|---------|-----------|
| 周期 `T` / 频率 `f` | 卡相邻两个同向过零点 → `f = 1/dx` |
| 峰峰值 `Vpp` | 卡同一周期的波峰和波谷 → `dy` |
| 电压增益 | `dy(输出曲线) / dy(输入曲线)` |
| 相位差 | 卡两曲线相邻同向过零点 → `φ = 360° × dx / T` |
| −3 dB 截止频率 | AC 曲线的 `Magnitude` 页找 `0.707 × 中频增益` 处 |
| 直流工作点 | 读曲线平台值；更准的做法是跑 `DC Operating Point` 分析 |

**两个坑**：

- **先点选曲线再拖游标**，否则 `dx/dy` 读的是另一条曲线的。
- **Maximum time step 太大**会让波形呈锯齿、读数偏小。一般取信号周期的 **1/1000**。

## Q9. 元件值到底该怎么写？为什么不能用 `1e-3`？

**已知结论**：部分 SPICE 导入器（含 Multisim 的）对 `1e-3` 这类科学计数法支持不一致，
但对**标准后缀**是稳定支持的。所以本项目硬约束第 4 条直接禁掉科学计数法。

| 想写 | 正确写法 | 错误写法 |
|------|---------|---------|
| 1000 Ω | `1k` | `1e3` |
| 0.001 A / 1 mΩ | `1m` | `1e-3` |
| 10 µF | `10u` | `10e-6` |
| 10 nF | `10n` | `1e-8` |
| 50 pF | `50p` | `50e-12` |
| 1 MΩ | `1MEG`（或 `1meg`） | `1e6` |

**例外**：`.MODEL` 行内部的参数**允许**科学计数法，`14.34F`、`7.306P`、`1E-14` 都是合法模型参数，
`cir_lint.py` 也**不检查** `.MODEL` 行。

## Q10. 为什么禁止 `.SUBCKT`？我想用运放/555 这种集成电路怎么办？

**原因**：`.SUBCKT` 会让 Multisim 导入器生成一个嵌套子电路块，
在 14.x 上经常导入失败、或导入后变成无法编辑的黑盒，且**和"导入后要手动换库件"的流程冲突**。

**替代方案 = 黑盒策略**：

1. 网表里只写一个**占位元件行**（如 `XU1 0 THR OUT ... NE555`），
   **不写** `.SUBCKT / .INCLUDE / .LIB`。
2. 导入后把它**替换成 Multisim 主数据库里的真实型号**
   （`Mixed / TIMER / LM555CN`、`Analog / OPAMP / 741`…）。
3. 这一步写进各电路 README 第 4 节的**第 1 步**，并在 README 顶部显式标注。

代价是：**这种网表在纯 SPICE 工具（ngspice / LTspice）里跑不了**，
因为引用的模型不存在。我们认为这个代价值得——本项目的目标是"能导入 Multisim"，
不是"能离线跑 SPICE"。003 电路就是这种情形的典型，README 顶部已经写得很清楚。

## Q11. 搜不到库路径里写的元件？

1. **版本/数据库差异**：Multisim 14.x 各版本、教育版、自定义安装的库内容不同，
   Family 名也可能略有出入（二极管和运放最明显）。
2. **用搜索框**：`Place → Component → Search`，勾选 **`Search in: All databases`**，
   输型号关键词（`2N2222` / `LM358` / `555`），比按树翻快十倍。
3. **模型缺失**：某些型号（如国产 S8050、SS8050）默认库没有，需要导入 SPICE 模型
   （`Tools → Component Wizard`）。**这种情况请换用本表里的通用型号**，别硬导。
4. 找到了不一样的真实路径 → **提 PR 修 `docs/multisim-library-map.md`**，这类修正最欢迎。

## Q12. 我只是想快速用现成电路，该看哪些文件？

```
circuits/NNN-xxx/
├── NNN-xxx.cir        ← File → Open 导入这个
├── README.md          ← 照第 4 节整理、第 5 节连线、第 6 节设仪器、第 7 节对数值
├── verification.md    ← 看状态标签 🟢🟡🔴 和理论/实测对照
└── prompt-used.md     ← 想改电路时，从这份提示词重新生成
```

**一定要先看 `verification.md` 的状态标签**：

- 🟢 已验证 = 有人真的跑通了，数值可信度高，可以直接用。
- 🟡 待验证 = 只过了语法 lint，**没人跑过**，请当作草稿。
- 🔴 验证失败 = 已知有问题，里面有原因说明。
